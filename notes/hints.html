NOTE 04 · HINTS

Hints piling up

Hints are the coordinator's copy of a write that a replica did not acknowledge. A pile of them means some node was down or too slow. The hints are the symptom. The down node is the problem. Deleting the symptom first can drop the only copy of those mutations.

What you are looking at

On a write, the coordinator stores a hint when a replica misses the ack and the miss is inside max_hint_window_in_ms. The default window is three hours. Hints live on the coordinator, under the hints directory in the data path, not on the node that was down. When that node comes back, coordinators replay the hints at it.

Two failures follow. Coordinators fill a disk with hint files. Or the node comes back and hint replay, plus the normal write load, stalls it again.

Confirm it

  1. On a coordinator that is growing disk, check the hints directory. The data path is often /var/lib/cassandra/hints. A directory that keeps growing is the pile. Snapshots and commitlog are different directories. Do not clear those because hints are large.
  2. nodetool tpstats and look at HintedHandoff. Pending work means replay is behind. Blocked or dropped means the coordinator is refusing new hints or falling behind.
  3. nodetool status. The usual cause is a DN node, or a node that just returned to UN and is now the target of every coordinator's replay.
  4. Note how long that node was down against the hint window. Past the window, coordinators stop storing new hints and expired hints will not replay. Inside the window, the files may be the only extra copy of writes the down replica missed.

Fix the target first

Bring the down replica back if the host and disks are fine. That is the start-and-repair path, not a replace. Hints replay on their own once it is reachable. If the host is gone, replace or remove it before you spend time on the hint files. Replaying at a node that will never return does nothing.

If the recovered node is falling over under replay, pause handoff on the coordinators that are sending it, not on the recovered node. The hint files are on the nodes that accepted the writes. Replay is those nodes pushing mutations at the replica that missed them. pausehandoff only stops the node you run it on. Pausing the recovered node stops hints it might send somewhere else. It does not stop the inbound replay.

nodetool pausehandoff

Run that on each coordinator whose hints directory is large or whose HintedHandoff pending is climbing. Let the recovered node become stable. Compaction and reads should settle. Then resume on those same coordinators:

nodetool resumehandoff

If resume floods it again, lower the throttle on the coordinators with nodetool sethintedhandoffthrottlekb, then resume. Pausing is a delay. It is not a delete. disablehandoff stops new hints from being stored. Use that only while you are in the incident, and turn it back on with enablehandoff. A cluster with handoff left disabled drops the safety net for the next outage.

Truncate only after the writes are safe

Truncating throws away stored hints on that coordinator. It does not repair anything.

nodetool truncatehints 10.1.2.21

That form drops hints for one endpoint. Omit the address and you drop every hint on this coordinator. Do it only in one of these cases:

  • The target has been down longer than the hint window, the hints are already expired, and disk is the emergency. You are deleting files that were not going to replay.
  • The target is back, a repair of its ranges has finished, and you have decided the repair is the copy you trust. Truncate is cleanup, not the repair.
  • You accept losing writes that no other replica acknowledged. At RF 3 and LOCAL_QUORUM, a hint is often the third copy, not the only copy. At RF 1, or if the other replicas also missed the write, it may be the only copy.

Run it on each coordinator that holds a pile, not once for the cluster. Hints are local files.

Done when

The node that was down stays UN. Hint directories stop growing. HintedHandoff pending falls and does not climb again. A truncated directory with the target still DN is not done. You removed the warning and left the outage.

Do not

  • Delete the hints directory out from under a running node. Use truncatehints. A removed directory can come back as a replay error or a restart problem.
  • Truncate hints for a node that has been down for twenty minutes and is your only missing replica. Those files may be the writes the other copies do not have.
  • Raise max_hint_window_in_ms during the incident to "stop the pile." A longer window stores more hints. It does not drain them.
  • Leave handoff disabled after the incident.
  • Pause handoff on the node that just came back. That node is the target. Pausing it does not stop the other nodes from replaying hints at it.

Hint file layout and the exact tpstats names differ by version. The commands above are the long-standing nodetool set. Confirm them against the version you run. This is a decision aid, not a procedure for a specific cluster.
